# Хостинг и удалённый доступ

[English](hosting.md) · Русский

По умолчанию мост слушает `127.0.0.1:25650`: до него достают только программы на машине сервера. Это безопасная
настройка, и её хватает, когда приложение агента запущено на том же компьютере, что и сервер. В остальных случаях
доведите агента до моста, не открывая мост в интернет:

| Как у вас устроено | Что советуем |
|---|---|
| Сервер на вашем компьютере или в домашней сети | Запустите агента на этом компьютере или оставьте мост на петле и пользуйтесь приложением агента на самом компьютере. |
| VPS или выделенный сервер с SSH | Туннель SSH с вашего компьютера: `ssh -N -L 25650:127.0.0.1:25650 you@server`, затем подключите агента к `http://127.0.0.1:25650/mcp` на вашем компьютере. Мост остаётся на петле. Или Tailscale на обеих машинах, а в `bridge.host` — адрес сервера в Tailscale. |
| Своя панель (Crafty, Pterodactyl, Pelican) | Туннель до машины, как выше, или выделенный порт на собственном адресе контейнера (`bridge.host`), доступный только с самой машины, с `bridge.allow_plain_http_off_loopback = true`. |
| Платный общий хостинг (без SSH) | Только дополнительный выделенный порт в открытом интернете, то есть сам мост открыт всем. Используйте его только с собственным HTTPS моста: сертификат на имя этого хостинга в `bridge.tls_cert` и `bridge.tls_key`. Без этого токены и коды входа идут через интернет открытым текстом — так нельзя. Прокси где-то ещё не поможет: до моста он всё равно пойдёт по обычному HTTP. |
| Бесплатный хостинг вроде Aternos | Не поддерживается: там только моды из его собственной библиотеки и нет дополнительных портов. |
| Облачные приложения агентов (claude.ai, ChatGPT в браузере, облачные агенты) | Публичный адрес HTTPS перед мостом: смотрите ниже и [cloud.ru.md](connect/cloud.ru.md). |

## Публичный адрес HTTPS

Облачные приложения подключаются с серверов своих разработчиков, поэтому им нужен публичный адрес HTTPS. Оставьте
мост на петле и поставьте перед ним готовый инструмент:

- На VPS с доменом: обратный прокси с автоматическими сертификатами, например Caddy:
  `mc.example.org { reverse_proxy 127.0.0.1:25650 }`.
- Без домена: Cloudflare Tunnel. Быстрый туннель (`cloudflared tunnel --url http://127.0.0.1:25650`) при каждом запуске
  получает новый адрес, и `bridge.public_url` придётся менять вместе с ним; именованный туннель сохраняет адрес.

Затем укажите `bridge.public_url = "https://mc.example.org"` в `config/almighty-common.toml` и перезапустите сервер,
чтобы вход и ссылки шли через публичный адрес. Этот адрес доступен всем в интернете; между ними и правами оператора
стоят только вход (код, который набираете вы) и токены агентов, поэтому прочитайте [Безопасность](security.ru.md).

За прокси или туннелем сервер видит всех клиентов как сам прокси: `/almighty agents` и уведомления о входе показывают
его адрес (обычно `127.0.0.1`), а блокировка за неверные токены считает всех внешних клиентов вместе (верный токен
проходит всегда, так что агенты продолжают работать). `allow_from` тоже видит адрес прокси.

## Собственный HTTPS моста

Если до самого моста нужно достать с других машин, дайте ему свой сертификат вместо прокси:

```toml
[bridge]
host = "0.0.0.0"
tls_cert = "certs/fullchain.pem"
tls_key = "certs/privkey.pem"
```

Файлы — это цепочка сертификатов PEM и незашифрованный закрытый ключ PKCS#8 (`BEGIN PRIVATE KEY`), например от
Let's Encrypt; пути считаются от папки сервера. Тогда мост говорит только по HTTPS, а вход и `/almighty connect`
используют `https`. Сам Almighty сертификаты не создаёт.

Без TLS мост запускается только на петле: с любым другим `bridge.host` он не запускается, а лог называет, что
исправить. В сети, куда достаёт только машина сервера (частный адрес контейнера, порт которого не опубликован),
укажите `bridge.allow_plain_http_off_loopback = true`, чтобы всё равно его запустить. Никогда не делайте так на
публичном адресе.

## Подтверждение входа на удалённом сервере

Код входа подтверждают там, где вы можете набирать команды на сервере: в игре или в консоли сервера (консоль панели
или терминал сервера через SSH; RCON считается консолью). На новом сервере первый оператор уровня 4, подтвердивший
вход в игре, становится владельцем. Из консоли назовите владельцем себя, подтверждая своё приложение:
`/almighty approve <код> <имя> owner <имя вашего игрока>`. Когда у сервера есть владелец, входы подтверждают только
консоль и владельцы, которые к тому же операторы уровня 4 ([Первые
шаги](getting-started.ru.md#3-подтвердите-вход-кодом)).

Токен агента, которым пользуются с известной машины, можно ограничить её адресами в `policy.toml`:

```toml
[agents.ci]
allow_from = ["203.0.113.7", "10.0.0.0/8"]
```

С любого другого адреса токен отклоняется и считается неверным.

## Несколько серверов, прокси, Bedrock

- За Velocity или BungeeCord у каждого сервера свой мост и свои агенты. С современной пересылкой (modern forwarding)
  Velocity укажите `identity = "proxy"` в `policy.toml`, чтобы игроки считались проверенными.
- Игроки Bedrock через Geyser и Floodgate — такие же игроки, как все, и считаются проверенными. Geyser для серверов с
  модами поддерживает только некоторые версии Minecraft; проверьте свою на его сайте.
