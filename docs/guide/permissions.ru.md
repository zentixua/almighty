# Права и политика

[English](permissions.md) · Русский

Агент может всё, что может оператор, и больше. Один файл, `config/almighty/policy.toml`, решает, сколько из этого он
использует, для кого и где. Он создаётся с комментариями при первом запуске. Отредактируйте его и выполните
`/almighty reload` или попросите ведущего его изменить ([ниже](#изменение-политики-просьбой)). Файл с ошибкой
отклоняется с точным текстом ошибки, а прежняя политика остаётся в силе.

## Роли

У каждого игрока и каждого агента одна из пяти ролей. Каждая включает всё, что дают роли ниже неё.

| Роль | У кого она без плагина прав | Что она даёт по умолчанию |
|---|---|---|
| владелец (`owner`) | Игроки из `owners` (проверенные), консоль | Всё: скрипты, правила со скриптами, любые команды |
| админ (`admin`) | Операторы уровня 3 или 4 | Смотреть на других игроков, боты в творческом режиме, откат чужих изменений, чтение журнала аудита, решения по просьбам сверх прав игрока |
| строитель (`builder`) | Операторы уровня 2 | Держать районы загруженными, ставить правила без скриптов, выполнять скрипты, одобренные владельцем |
| участник (`member`) | Каждый проверенный игрок на сервере друзей | Строить, выдавать себе предметы, боты в режиме выживания, говорить со всеми, писать памятки мира |
| гость (`guest`) | Каждый проверенный игрок на публичном сервере, каждый непроверенный игрок | Смотреть на мир, читать памятки, получать личные ответы, выполнять команды на своём уровне оператора |

Команды всегда проходят собственные проверки прав ванильной игры: просьба выполняет свои команды на уровне оператора
самого просящего или на уровне его роли, если он выше (владелец 4, админ 3, строитель 2, участник и гость 0), но
никогда выше потолка агента. Без просьбы агент выполняет команды на уровне своего пола.

Владельцы указываются по UUID, а не по имени. Добавить владельца — `/almighty owner add <player>` в консоли (игрок
должен хотя бы раз зайти на сервер). `/almighty role <player> <role> [duration]` даёт роль на время, например
`/almighty role Alex builder 3h`; админы могут давать только роли ниже своей, и роль владельца так дать нельзя никому.

### Проверенные игроки

`identity` в `policy.toml` задаёт, какие игроки считаются проверенными:

| Значение | Проверены |
|---|---|
| `auto` (по умолчанию) | Игроки с UUID учётной записи Mojang на сервере с `online-mode` и игроки Bedrock через Floodgate |
| `mojang` | То же, без Floodgate |
| `proxy` | Как `auto`, для сервера за Velocity с modern forwarding (его собственный `online-mode` выключен) |
| `offline` | Все: вы ручаетесь за каждое имя, например в офлайн-сети LAN среди друзей |

С `auto` или `mojang` на сервере с `online-mode=false` проверенных нет, потому что там любой клиент может назваться
любым UUID. Непроверенный игрок — гость, что бы ни говорили его роль или плагин прав.

## Пресеты

`preset` задаёт, что агент делает, когда никто не просил: по собственной инициативе или по тексту игроков, который он
читает в чате.

| Пресет | Без просьбы агент действует как | Для чего |
|---|---|---|
| `private` | Свой потолок (ниже) | Сервер, где с агентами говорят только владельцы |
| `friends` | Участник | Сервер среди знакомых людей. Новая установка начинает с него |
| `public` | Гость | Сервер, открытый для всех |

С просьбой игрока иначе: агент прикладывает тикет сообщения этого игрока, и вызов выполняется с правами этого
игрока. Тикет только сужает права: больше потолка агента он не даёт никогда.

## Агенты: потолок и пол

```toml
[agents.gm]
ceiling = "owner"

[agents.codex]
ceiling = "admin"
floor = "builder"
```

- **Потолок** (`ceiling`) — самое большее, что агент может сделать, кто бы ни просил. У агентов, которых нет в
  списке, потолок `admin`; у агента по умолчанию `gm` в шаблоне стоит `owner`.
- **Пол** (`floor`) — то, что агент может без просьбы. Без него решает пресет; выше потолка пол не бывает.

### Ваше приложение

`/almighty approve <code> <name> owner` добавляет этому приложению `ceiling = "owner"`. На сервере друзей или
публичном сервере приложение без просьбы всё равно действует как участник или гость, потому что текст игроков может
дойти до него через ленту событий. Когда вы просите в игре командой `/gm`, ваша просьба несёт ваши права владельца.
Чтобы приложение действовало с вашими правами во всём, добавьте `floor = "owner"` в его `[agents.<name>]` и
выполните `/almighty reload`; делайте так только для приложения, за которым вы следите, ведь тогда чат игроков может
заставить его действовать с вашими правами.

## Возможности

Каждая возможность — узел прав `almighty.<name>`. Без плагина прав каждый узел решается по лестнице ролей по своей
роли по умолчанию.

| Узел | Роль по умолчанию | Даёт |
|---|---|---|
| `almighty.knowledge` | гость | Читать памятки, каталог сервера и ленту событий |
| `almighty.observe.world` | гость | Смотреть на мир: состояние, карты, виды, блоки, сущности, работы |
| `almighty.speak.reply` | гость | Отвечать игрокам лично |
| `almighty.command` | гость | Выполнять команды и функции на уровне оператора самого просящего |
| `almighty.policy` | гость | Читать собственные файлы Almighty и предлагать в них изменения |
| `almighty.notes.write` | участник | Писать памятки мира |
| `almighty.speak.all` | участник | Говорить со всеми, заголовки |
| `almighty.build` | участник | Строить и откатывать свои постройки |
| `almighty.give.self` | участник | Выдавать предметы просящему |
| `almighty.bots` | участник | Боты в режиме выживания или приключения |
| `almighty.area` | строитель | Держать районы загруженными |
| `almighty.rules` | строитель | Правила без скриптов |
| `almighty.scripts.run` | строитель | Выполнять скрипты, одобренные владельцем |
| `almighty.observe.players` | админ | Смотреть на других игроков: где они и что видят |
| `almighty.bots.admin` | админ | Боты в творческом режиме и режиме наблюдателя, пакеты клиента, скины |
| `almighty.undo.any` | админ | Откатывать изменения других агентов и игроков |
| `almighty.audit` | админ | Читать журнал аудита |
| `almighty.approve` | админ | Решать просьбы сверх прав игрока (`ask_admin`) |
| `almighty.engine` | владелец | Скрипты и правила со скриптами: код в процессе Java сервера |

### LuckPerms

Если стоит LuckPerms, эти узлы для игроков решает он, например
`/lp group default permission set almighty.build false`. На Fabric Almighty обращается к LuckPerms через
fabric-permissions-api, который даёт сам LuckPerms. Непроверенный игрок остаётся гостем, что бы ни выдал плагин.
Без плагина прав роли берутся из лестницы выше и из `/almighty role`.

## Подтверждения

Просьба игрока выполнить команду выполняется сразу, когда каждая команда в ней безвредна или направлена только на
самого просящего:

- безвредные: `time`, `weather`, `say`, `me`, `msg`, `tell`, `w`, `teammsg`, `tm`, `list`, `locate`, `playsound`,
  `stopsound`, `particle`, `help`, `trigger`, `seed`, `setblock`, `fill`, `clone`, `place`, `fillbiome`;
- только на просящего (`@s`, его имя или UUID): `tp`, `teleport`, `give`, `effect`, `clear`, `gamemode`, `xp`,
  `experience`, `enchant`, `kill`, `spawnpoint`, `title`, `ride`, `attribute`, `item`, `advancement`, `recipe`.

Всё остальное (другой игрок в качестве цели, любая команда мода, `data`, `summon`, `function`, `ban` и так далее)
ждёт подтверждения просящего. Сервер показывает ему точный вызов с `[Allow]` и `[Deny]`; ответить может только этот
игрок, в течение 2 минут. Одновременно ждать могут не больше 3 просьб на игрока и 20 на агента.

`[safety]` это настраивает:

```toml
[safety]
ask_admin = ["kick"]       # these may go to an admin when the player lacks the right
confirm_first = ["tp"]     # these always need the requester's confirmation
```

Просьба из `ask_admin` сверх прав игрока уходит админам с `almighty.approve` одной тихой строкой в чате не чаще раза в
10 минут; они видят её в `/almighty inbox`. Одобренная просьба выполняется один раз с правами этого админа. Пустой
`ask_admin` (по умолчанию) значит, что такие просьбы просто отклоняются.

## Зоны

```toml
[zones.spawn]
dim = "overworld"
from = [-64, -64, -64]
to = [64, 320, 64]
deny = ["build", "area"]

[zones.arena]
from = [5000, -64, 5000]
to = [5400, 320, 5400]
agent_may = ["build", "bots"]
```

- `deny` (любые из `build`, `area`, `bots`, `bots.admin`, `command`) запрещает эти возможности внутри рамки всем ниже
  владельца. Команда проверяется там, где выполняется, и в каждой координате, которую называет; команды, которые
  меняют место выполнения (`execute as`, `at`, `positioned`, `in`), отклоняются, пока хоть одна зона запрещает
  `build` или `command`. Селекторы сущностей не проверяются.
- `agent_may` (любые из `build`, `area`, `bots`, `bots.admin`) позволяет агенту пользоваться этими возможностями
  внутри рамки самому, даже когда его пол этого не позволил бы: это его собственная арена.
- `dim` по умолчанию — Верхний мир.

## Квоты

```toml
[quotas]
build_blocks = 50000
give_items = 128
```

Сколько блоков могут построить просьбы одного игрока и сколько предметов ему могут выдать за час. У владельцев квоты
нет; собственные постройки агента делят одну общую норму.

## Приваты

Если стоит Open Parties and Claims или FTB Chunks, постройка ниже владельца идёт только на чанках, где просящему
игроку можно строить; постройка без просьбы — только на чанках без привата.

## Ограничения содержимого

Ниже владельца, что бы ни говорила политика:

- постройки ставят только простые состояния блоков (без данных блок-сущностей) и никогда не ставят блок из тега
  `#almighty:never_build`: командные блоки, блоки структур и мозаики, спавнеры, барьер, свет, бедрок, порталы, рамки
  портала в Энд и укреплённый глубинный сланец;
- `give` выдаёт просящему не больше одного стака простого предмета и никогда не выдаёт предмет из
  `#almighty:never_give` (командные блоки, блоки структур, барьер, свет, отладочная палочка, спавнеры, бедрок и
  подобное) или яйцо призыва;
- текст чата и команды не могут нести действия по щелчку, которые выполняют или предлагают команды, и префикс
  `[Almighty]`, которым сервер помечает свои собственные запросы.

Датапаки могут добавлять записи в оба тега.

## Правила для игроков

Правило без скрипта (условия на событие и действия: отменить, записать в ленту, сказать, выполнить команду)
принадлежит тому, кто о нём попросил. Права его создателя проверяются заново на каждом событии: правило отменяет
только там, где создатель может строить, выполняет команды от его имени, перестаёт работать, когда он теряет
`almighty.rules`, и истекает не позже чем через 7 дней. У правил владельцев срока нет.

Скрипты из `config/almighty/scripts/<name>.groovy` выполняются по имени для любого, у кого есть
`almighty.scripts.run`, после того как вы одобрите их командой `/almighty script approve <name>`, и только пока файл
не изменился. Одобренный скрипт выполняется с полными правами: это ваш код.

## Изменение политики просьбой

Ведущий может читать и править `policy.toml` (а для владельцев ещё и скрипты в `config/almighty/scripts/`):

- **Ваша просьба** (вы владелец и просите в игре командой `/gm`) применяется сразу.
- **Собственное предложение агента** применяется сразу, только если оно ограничивает. Всё, что даёт больше (более
  открытый пресет, новый владелец, выше потолок или пол, меньшая запрещающая зона, шире арена, больше квоты), ждёт, пока
  обладатель `almighty.engine` не разрешит это в игре; вы видите краткое описание изменения.
- **Просьба игрока** изменить политику отклоняется.

Каждая запись сначала проверяется; прежний файл уходит в `config/almighty/policy.history/` (хранятся 50), а
`/almighty policy undo` возвращает его. Поднять агенту потолок до владельца можете только вы, в файле или командой
`/almighty approve <code> <name> owner`.
