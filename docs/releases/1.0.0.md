Almighty 1.0: an AI game master for your Minecraft server, now for current Minecraft and for Fabric, with a
permission system that makes it safe to share with friends or the public. Server only: players install nothing.

## Files

Pick the jar for your server's game version and loader:

| Minecraft | NeoForge | Fabric |
|---|---|---|
| 1.21.1 | `almighty-1.0.0+1.21.1-neoforge.jar` (NeoForge 21.1.264+) | — |
| 26.1.2 | `almighty-1.0.0+26.1.2-neoforge.jar` (NeoForge 26.1.2.130+) | `almighty-1.0.0+26.1.2-fabric.jar` (Fabric Loader 0.20.1+, Fabric API) |
| 26.3 | `almighty-1.0.0+26.3-neoforge.jar` (NeoForge 26.3.0.118+) | `almighty-1.0.0+26.3-fabric.jar` (Fabric Loader 0.20.1+, Fabric API) |

Java 21 for 1.21.1, Java 25 for 26.x (as the game itself needs).

## Connect any agent app, no setup

- The mod serves MCP itself at `http://127.0.0.1:25650/mcp`: tell Claude Code, Codex (also in the ChatGPT desktop
  app), Cursor, VS Code or another MCP app "connect to my Minecraft server at …" and it adds the server.
- Sign-in is the standard MCP login: the app opens a page with a four-digit code and you type
  `/almighty approve <code>` on the server. No tokens to copy, no config files, no adapter.
- `/almighty connect` shows every way to connect; headless runs (`claude -p`, `codex exec`, CI) use an agent token
  (`/almighty agent add <name>`).
- Several agents at once, each with its own token, presence (`/almighty agents`) and rights. HTTPS with your own
  certificate (`bridge.tls_cert`, `bridge.tls_key`), or behind your reverse proxy or tunnel (`bridge.public_url`).

## Who may make it do what

- `config/almighty/policy.toml` picks a preset. **New servers start as `friends`**: anyone may talk to the game
  master, members' everyday requests run at once, anything bigger asks the right person with one click.
  **`public`** is for servers open to strangers. **Servers updating from 0.4 keep `private`**, so nothing changes for
  them.
- A player's request runs with that player's own rights, never more: the game master cannot be talked into doing
  for someone what they may not do themselves. Irreversible actions for other people wait for the requester's
  confirmation in chat; admin-level requests can go to an admin as one quiet digest.
- Every capability is a permission node `almighty.<capability>` (LuckPerms on NeoForge, and on Fabric through
  fabric-permissions-api). Without a permission plugin: `/almighty role <player> <role> [duration]`.
- Zones (no building at spawn, an arena of its own), hourly quotas, and claims of Open Parties and Claims or FTB
  Chunks are respected. Command blocks, spawners, barriers and similar blocks are never built for a player; items
  go only to the player who asked.
- The owner can change all of this by asking the game master in plain words; changes that grant more wait for the
  owner's confirmation, and `/almighty policy undo` walks back.

## Safety

- Every block the game master changes is journaled on disk and can be undone, also after a crash; undo leaves alone
  blocks someone changed since (`changes`, `/almighty undo <change>`).
- Every call with effects and every refusal is in the audit log (`/almighty log`); `/almighty pause` is the red
  button.
- Commands known to crash or freeze a server are refused for every agent; game master work never takes more than its
  share of a tick and backs off when the server lags.
- A command the agent may not run at its level says so (`needs_level`, with a hint), instead of vanilla's
  "Unknown or incomplete command".
- Rules without code (conditions and actions) for everyone below the owner, bound to the person who asked for them;
  owner-approved scripts by name.

## Learns your modpack

`notes {query}` gives the agent the running server's mods, blocks, items, recipes, commands, events and config.
Mods and datapacks can ship notes for agents at `data/<namespace>/almighty/notes/<name>.md`; the world keeps the
game master's own notes.

## Fabric

Everything works on Fabric too. Rules there react to any Fabric API or mod callback (on NeoForge: any event) whose
answer can stay neutral while a rule only listens, and cancelling makes the callback return its "stop" value. Bots on Fabric receive vanilla packets only (mod packets need
NeoForge's channel negotiation for in-memory connections).

## Upgrading from 0.4.0

Replace `almighty-0.4.0.jar` in `mods/` with the jar for your version and loader. Your `policy.toml` is written with
`preset = "private"`, which keeps today's behaviour; read [Security](https://github.com/zentixua/almighty/blob/main/docs/guide/security.md)
before switching to `friends` or `public`. The Python adapter `mcp/almighty.py` and the `mcp/gm` kit still work but
are no longer needed: connect your app to `/mcp` directly.
