# Ведущий: голос, исполнители, наставник

Набор, который делает из моста Almighty живого ведущего сервера на Claude: игроки зовут его в чате или пишут лично
(`/gm`), он отвечает за секунды, делает их просьбы в мире, говорит «готово» только по проверке в мире и учится на
каждом разговоре. Только Python 3.11+ и `claude` (Claude Code) на сервере; модели — по подписке владельца.
Набор — общий для любого сервера; своё у сервера — его каталог (настройки, знания, рецепты, плагины).

## Как устроен
```
игроки ── лента моста ──▶ диспетчер (gmd.py, без ИИ) ──▶ голос (claude -p, один живой процесс)
                              │   ▲                         │ reply — единственный, кто говорит
                              │   └── итоги задач ◀──┐      │ task — долгое исполнителю
                              ▼                      │      ▼
                         очередь (gm.db) ──▶ исполнители (свежий claude -p на задачу, ≤2)
                              │
                         опыт ──▶ наставник (claude -p в копии знаний) ──▶ ворота (gate.py) ──▶ навык
```
- **Диспетчер** (`gmd.py`) — служба: слушает ленту моста, будит голос только на сообщения ведущему (личное `/gm`;
  в чате — по имени из `gm.names`, кто говорит с ведущим — 90 с без имени), ведёт очередь задач с ресурсами и
  сроками, пишет всё в журнал: время ответа, цену, итоги.
- **Голос** — единственный, кто говорит с игроками (`reply`): отвечает, смотрит мир, делает мгновенное (рецепты
  `instant`), ставит задачи. Перезапуск в паузе — после `voice_turns` ходов и после правки навыка.
- **Исполнители** — свежая сессия на задачу: рецепт или рычаги, `progress`, конец — `done` с проверкой в мире
  (мост выполняет её сам, ответ — доказательство) или `fail`. Итог голосу, он говорит игроку.
- **Наставник** — после нового опыта (уроки сессий, ошибки, отказы охраны, брошенные задачи, молчание голоса,
  долгие ответы, каждые 8 сообщений): правит знания сервера в отдельной копии (git worktree), рецепты пробует на
  тестовом сервере. Правка входит в навык только через **ворота** (`gate.py`):
  1. порядок: только свои файлы, `evals/learned.jsonl` и `rules.local.md` — только дописать, `CORE.md` — коротко,
     каждый новый рецепт — с удачной пробой этого же текста;
  2. проверочный набор (`evals/base.jsonl` набора, `local.jsonl` и `learned.jsonl` сервера): голос с новым навыком не хуже
     прежнего, случаи урока проходят; голос не ответил (сбой, предел подписки) — правка не принята, итоги без
     ответа не запоминаются (память итогов — по навыку, набору, модели и опросу);
  3. независимый рецензент — `clean`; его промпт — из принятого навыка, дифф — целиком (больше 60 000 знаков —
     отказ: разбить).
  Принятая правка — коммит в git каталога сервера; откат — `git revert`.
- **Охрана** (`guard.py`, хук PreToolUse каждой сессии через `hook.py`, и проверка шагов рецептов): один голос
  (никаких `/say`, `/tellraw`, чата ботов, сообщений из скриптов у других); не ломать сервер (`/stop`, `/reload`,
  `save-off`, `save-all flush`, `forceload add` — никогда); `op`, белый список, баны и кики — только по слову
  владельца (чей запрос — по очереди, не по тексту); макрос функции проверяется таким, каким станет, команды из
  скрипта — только строкой целиком (`gm.command('…')`), командных блоков нет; скрипты без загрузки чанков, потоков,
  задач на потом, слушателей шины, процессов и файлов; голос не строит, не водит ботов, не грузит районы и не ставит
  правила сам; наставник правит только свои файлы. `guard` в config.toml сервера эти запреты только дополняет;
  свои проверки сервера — плагины (ниже). Сломалась сама охрана или плагин — отказ (код 2: иной код и срок хука
  Claude Code вызов пропускают).

## Навык
`skill/` — навык Claude Code (`SKILL.md`, имя `gm`; его можно поставить и в обычный Claude Code):
- `SKILL.md` — ядро: как работать отлично, решение на каждое сообщение, инструменты;
- `RULES.md` — правила, которые уроки не меняют; `roles/` — голос, исполнитель, наставник, рецензент;
- `levers.md` — рычаги Almighty глубоко: что как делается и как проверить;
- `recipes/` — проверенные способы (формат — `recipes.py`): шаги — вызовы моста, проверка — Groovy в мире.
Знания сервера (каталог сервера, его git): `skill/CORE.md` (выученное, в каждом ходе голоса),
`skill/knowledge/*.md`, `skill/recipes/*.md` (рецепт сервера перекрывает рецепт набора с тем же именем),
`skill/rules.local.md`, `evals/learned.jsonl` — их ведёт наставник; `evals/local.jsonl` (случаи сервера) и
`plugins/` пишут только люди. Общий опыт — после игрового дня PR сюда (ядро, рычаги, рецепты без привязки к
серверу и его модам).

Сессии чистые: свой системный промпт (роль + ядро + правила + выученное + список рецептов), без памяти Claude Code, без CLAUDE.md,
без чужих навыков и настроек (`--setting-sources project`, `--strict-mcp-config`, `--disable-slash-commands`),
права — `dontAsk` с разрешёнными MCP, чтение — только каталоги навыка, токены моста — запрет чтения.

## Поставить на сервер
```sh
uv run mcp/gm/gm.py init ~/gm                       # каталог сервера: config.toml, skill/, evals/, git
$EDITOR ~/gm/config.toml                             # мост, тестовый мост, владельцы, языки игроков, плагины
uv run mcp/gm/gate.py --config ~/gm/config.toml evals   # набор на голосе (--fresh — заново)
cp mcp/gm/systemd/gm.service ~/.config/systemd/user/ && systemctl --user enable --now gm   # пути в нём — свои
```
Тестовый сервер (`test_bridge`) — копия мира на своём порту: на нём наставник пробует рецепты; без него рецепты не
учатся (знания и правила — учатся). Репетиция ботами — там же: ботов ведущий не слушает, кроме названных в
`gm.bot_players`. Люди: `gm.py tasks`, `gm.py log --last 50`, `gm.py recipes`,
`gm.py run <рецепт> '{…}' [--test]`.

## Плагины сервера
Своё у сервера (запреты по его модам, свои инструменты, своя работа диспетчера) — не правкой набора, а плагинами:
файлы Python в каталоге сервера, `[gm] plugins = ["plugins/my_checks.py"]` в config.toml (пути от каталога
сервера). `plugins.py` грузит их стандартно (`importlib.util.spec_from_file_location`) один раз на процесс; плагин —
обычный модуль с любыми из функций:

| Функция | Когда | Ответ |
|---|---|---|
| `check_command(seg, ctx)` | каждая часть команды (`execute … run …`), откуда бы она ни пришла: `command`, строки функции и макросы, команды-литералы скриптов и правил, чат бота, шаги рецептов | причина отказа или `None` |
| `check_call(method, params, ctx)` | вызов моста целиком, после проверок набора | причина отказа или `None` |
| `after_call(store, method, params, ctx)` | после разрешённого вызова на живом мосту (хук сессии, шаги рецептов; у наставника — нет) | — |
| `tools(gm, safe)` | запуск MCP-сервера `gm`: свои инструменты, `@safe def имя(...)` → `mcp__gm__имя`; ошибка — `plugins.PluginError` | — |
| `tick(host)` | каждый круг диспетчера: `host.cfg`, `host.store`, `host.bridge`, `host.notify(player, text, task=None)` — весть голосу | — |

```python
# plugins/no_tnt.py — ведущий не ставит и не призывает TNT
import re

def check_command(seg, ctx):
    if re.search(r"\btnt\b", seg, re.I):
        return "TNT на этом сервере ведущий не трогает"

def check_call(method, params, ctx):
    if method == "build" and "tnt" in str(params.get("ops")):
        return "TNT на этом сервере ведущий не трогает"
```
Сначала проверки набора, потом плагины по порядку списка; решает первый отказ — ослабить проверку набора плагин не
может (имена инструментов набора тоже). `ctx` — кто действует: `ctx.role`, `ctx.requester`, `ctx.owner()`,
`ctx.cfg` (весь config.toml: свои настройки плагин держит в своём разделе). Модули набора (`guard`, `store`)
плагин импортирует внутри своих функций — тогда тот же файл годится и как командная строка. Разбор команд —
`guard.segments`, числа в параметрах — `guard.numbers`. Плагин не загрузился (нет файла, ошибка в коде) или его
проверка упала — охрана отказывает во всём, `gmd` не стартует, причина — в журнале: проверки сервера не пропадают
молча. Наставник плагины не правит (их нет в его файлах).

## Проверки
`python3 -m unittest discover -s mcp/gm/tests` (CI — на каждый PR): охрана (речь, запреты, владелец, скрипты,
правка файлов, хук как процесс), плагины, рецепты, очередь, ворота, роли и весь путь с заглушками
моста и claude — сообщение → ход голоса → задача → исполнитель → итог голосу, и урок → ворота → навык.
Флаги и хуки Claude Code — по https://code.claude.com/docs/en/cli-reference, …/hooks, …/permissions.
