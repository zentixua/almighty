# Рычаги Almighty — глубоко и без ошибок

Мост даёт ведущему всё, что может игрок и оператор, и код в самой игре. Здесь — как пользоваться каждым рычагом,
чтобы получалось с первого раза. Памятки модов сервера (notes) — их команды и механики.

## Смотреть
- **status** — сервер: tps и mspt (20 и <50 — хорошо), игроки, чанки и сущности по измерениям, время, погода,
  работы ведущего. **status player** — игрок: место, измерение, здоровье, режим, инвентарь по слотам, эффекты,
  точка возрождения, на какой блок смотрит. Прежде чем делать «у игрока» — посмотреть, где он и куда смотрит.
- **entities** — вокруг center [x, y, z] в radius или в рамке; type — фильтр. Только загруженные места.
- **view map** — карта сверху (center [x, z], size до 1024); серая шахматка — чанк не загружен. **view look** —
  рамка с направления (фасад, план, разрез). **view blocks** — блоки рамки текстом (до 64 по оси); тот же вид
  принимает build (layers). **view eye** — глазами игрока, бота или свободной камеры: что под прицелом, какие
  сущности видны и где (угол от взгляда), картинка.
- **events** — лента: chat, gm (личное ведущему), join/leave, death (причина, убийца), advancement, dimension,
  command (что набрал игрок), job (конец работы), emit (правила и скрипты), rule.off/rule.error, lag.

## Делать командами
- **command commands** — команды по порядку от имени ведущего (права 4), источник — точка появления мира или pos.
  Каждая отвечает ok, result, output, errors: ok=false — читать errors и исправлять причину.
- Относительно игрока: `execute as <имя> at @s run <команда>` (~ ~ ~ — у игрока, ^ ^ ^ — по его взгляду:
  `^ ^ ^10` — 10 блоков перед ним). Другое измерение: `execute in minecraft:the_nether run …`.
- **command lines** — функция из строк без файла и /reload; строки с `$` — макросы `$(имя)` из args (целые —
  целыми). Для пачки команд с общими параметрами.
- Свойства NBT в 1.21.1: CustomName — JSON-строкой (`CustomName:'"Боб"'`), предметы — компонентами
  (`diamond_sword[enchantments={levels:{sharpness:5}}]`). Ошибка разбора называет место — читать её.
- Тяжёлое (большой /fill, /clone) — не командой: build делит работу по тикам, сервер не встаёт.

## Код в игре — script (Groovy)
- Переменные: server, gm (gm.command('…'), gm.commandAs(entity, '…'), gm.emit(data), gm.player('Имя'),
  gm.bot('имя'), gm.level('minecraft:the_nether')), state (общая карта до перезапуска), args. Импортированы
  BlockPos, Blocks, Items, ItemStack, Entity, EntityType, LivingEntity, ServerPlayer, ServerLevel, Vec3, AABB,
  Component, CompoundTag, BuiltInRegistries, ResourceLocation.
- Вернуть данные — последним выражением или return (карта и список → JSON); println — в output.
- Игрок: `def p = gm.player('Steve')` (null — не в игре); `p.blockPosition()`, `p.getLookAngle()`,
  `p.serverLevel()`, `p.getVehicle()`, `p.getInventory().countItem(Items.DIAMOND)`.
- **Чанки не грузить.** Читать блоки и высоту — только в готовом чанке:
  `lvl.getChunkSource().getChunkNow(x >> 4, z >> 4) != null`, иначе getBlockState и getHeight грузят чанк
  синхронно и сервер встаёт. Далёкое место — area prepare, потом читать.
- Сущности рядом: `lvl.getEntitiesOfClass(LivingEntity, new AABB(x1, y1, z1, x2, y2, z2))`.
- Срок — timeout_ms (до 10 с), цикл прерывается; отката нет — большие правки блоков через build.
- **Ничего не отдавать игре на потом**: замыкания и объекты скрипта (тикеты, сравнения, слушатели, Runnable,
  server.execute) игра позовёт без срока, ошибка уронит тик. Реакция на события — rule.
- Первый запуск дольше (5–80 мс: Groovy связывает вызовы) — это нормально.

## Реакции и шоу — rule
- rule add: event — класс события коротким именем (`LivingDeathEvent`, `BlockEvent.BreakEvent`,
  `PlayerEvent.PlayerLoggedInEvent`) или "tick"; найти класс — rule types query. script — Groovy с event;
  `event.canceled = true` отменяет отменяемое (запреты — priority "highest").
- Шоу во времени — tick с every (раз в N тиков) и limit (снять после N раз): салют каждые 10 тиков 300 раз — ровно
  минута сорок, без живой сессии. Счётчики — в state. name — то же имя заменяет правило; убирать по name.
- Бюджет: среднее время за тик (budget_ms, 5 мс по умолчанию); превышение, 10 ошибок подряд или поток в ленту
  выключают правило (rule.off с причиной) — смотреть rules и чинить причину, а не поднимать бюджет.
- persist — только то, что должно пережить перезапуск сервера (по просьбе игрока или владельца).
- Команда из правила, вызванного командой, идёт сразу (мост это делает сам) — итог виден в том же запуске.

## Строить — build
- ops по порядку: fill (from, to, block, mode replace|keep|hollow|outline), set (pos, block со свойствами),
  layers (origin, palette символ → блок, layers снизу вверх; символ не из палитры — не трогать). Ответ — номер
  работы; откат — build undo. Чанки ждёт сам (не дольше 2 минут).
- Постройка ставит места как /fill: содержимое сундуков и т. п. в рамке пропадает; откат возвращает блоки и
  содержимое, но не сущности и не то, что отвалилось за рамкой.
- Перед стройкой — view blocks/look места: не строить в чужом, на воде без опоры, на игроке.
- Большое — частями (фундамент, стены, крыша) с view между частями.

## Далёкие места — area
- area prepare start/end [x, z] — загрузить чанки рамки в фоне и держать ttl_seconds (до часа); wait — ждать
  готовности. Нужно, чтобы смотреть картой, читать блоки и строить там, где никого нет. Отпускать — area release.
- Моды, которые сами грузят свои районы (удары Airstrike), этого не требуют.

## Боты — bot
- spawn (имя, pos, gamemode, skin) — игрок с пометкой [бот] в табе; входит как игрок, делает всё руками: act —
  программа шагов (hold/release клавиш, look_at, click attack/use, slot, menu, chat «/команда», walk_to, press
  клавиши транспорта мода, payload — пакет мода). state — тело, инвентарь, транспорт, меню, почта.
- Транспорт: сесть — click use по нему, слезть — sneak; лошадь, лодку, свинью, верблюда бот ведёт клавишами;
  самолёты Immersive Aircraft — left/right, jump/sneak, forward/back.
- Права бота — права его игрока: команда бота с правами — только если боту их выдали.
- Убрать бота, когда дело кончилось (remove).

## Работы — job
Долгое (постройка, снимок, откат) отвечает описанием, если не успело за wait: дальше job id с wait. job без id —
идущие и последние. Отмена — job cancel (сделанное остаётся).

## Проверка «готово» — по миру
- Появилось существо или машина — entities у места с type.
- Предмет у игрока — status player (инвентарь).
- Постройка — view blocks или look рамки.
- Игрок на транспорте — script `gm.player('Имя').getVehicle()?.getType()?.toString()`.
- Игрок это видит — view eye who=<игрок>: entities in_view и visible.
- Правило живо — rule list (state on).

## Ловушки
- Координаты «у игрока» — его место из status player, а не 0 0 и не точка появления.
- ~ и ^ в команде без execute at — от точки появления мира, а не от игрока.
- Чанк вдали от игроков не загружен: entities там пусты, view — шахматка, блоки — '?'. Это не «пусто», это «не видно».
- Участки кораблей Sable (x от 20 000 000) — не строить, не грузить, не телепортировать.
- Одинаковая команда с ошибкой трижды — признак неверного понимания: прочитать errors, notes мода, пробовать иначе.
